# Безопасность

## Как сообщить об уязвимости

Не заводите публичную задачу. Используйте приватный канал:

- [GitHub Security Advisory](https://github.com/qwe8nxtroud/multigate/security/advisories/new) — предпочтительно;
- либо личное сообщение в [сообществе VPN HUB](https://t.me/vpnhub_community).

Ответ — в течение 72 часов. Исправление критичных находок выходит отдельным релизом,
с указанием автора находки, если он не против.

## Что считается уязвимостью

- Обход входа в админку, повышение прав, угон сессии.
- Утечка токена API панели, пароля админа или ссылок подписок: в HTML, журнале, ответах API.
- Получение чужой подписки: через кэш, подмену User-Agent, перебор идентификаторов.
- Инъекции: SQL, подстановка пути в запрос к панели, SSRF при ретрансляции вебхуков.

## Что уязвимостью не считается

- Доступ к данным при уже полученном доступе к серверу или базе прослойки.
- Отсутствие ограничения скорости на эндпоинтах, не связанных со входом.
- Находки в самой панели Remnawave — сообщайте [разработчикам панели](https://github.com/remnawave).

## Модель угроз, коротко

Токен API панели хранится в базе прослойки. Доступ к серверу прослойки равносилен доступу
к панели в объёме прав этого токена. Отсюда исходные требования установки:

- админка не должна торчать в интернет без нужды: по умолчанию прослойка слушает `127.0.0.1:8080`;
- токен панели выдавайте с минимальными правами (панель 2.8.0+ это позволяет);
- базу держите на своём сервере, резервные копии шифруйте: в них тот же токен.
