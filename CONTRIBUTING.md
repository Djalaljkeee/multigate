# Участие в разработке

Спасибо за интерес. Проект небольшой, правила простые.

## Перед тем как писать код

Заведите задачу и опишите проблему из практики: какой клиент, какая панель, что пошло не так.
Прослойка стоит между чужим приложением и чужой панелью — почти всякая правка упирается
в поведение, которое задано снаружи, и его лучше обсудить до реализации.

Вопросы по установке и настройке — не в задачи, а в [сообщество](https://t.me/vpnhub_community):
там отвечают быстрее.

## Сборка и проверки

```bash
make build   # бинарник
make check   # go vet и тесты — это же гоняет CI
make test    # только тесты
```

Требуется Go версии из `go.mod`. Перед отправкой:

- `gofmt -l .` не должен ничего печатать;
- `make check` проходит;
- новая логика закрыта тестом рядом с кодом (`*_test.go` в том же пакете).

## Что важно при правках

- **Данные в панели.** Грейс и выдача сквадов меняют живую панель. Любая правка здесь
  должна переживать повторный вызов и падение на середине: сначала снимок исходного
  состояния, потом изменение.
- **Форматы подписки.** Конфиг ломается тихо: клиент просто не подключается. Меняете
  `internal/subfmt` — добавьте тест с реальным ответом панели.
- **User-Agent.** Неизвестный клиент должен получать рабочий конфиг, а не пустой ответ.
- **Секреты.** Токен панели и пароли не должны попадать в шаблоны, журнал запросов
  и ответы API. В `internal/admin/secret_leak_test.go` это проверяется — не ослабляйте тест.
- **Миграции.** Только вперёд, идемпотентно, без потери данных на живой базе.

## Стиль

Пишите как написан соседний код: те же приёмы, та же плотность комментариев.
Комментарий объясняет причину, а не пересказывает строку. Сообщения коммитов — по-русски,
в повелительном наклонении, одной строкой по существу.
